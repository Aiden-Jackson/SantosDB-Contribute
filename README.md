# SantosCAD

SantosCAD is a community resource directory for FiveM.

Find scripts, EUP, vehicles, MLOs, YMAPs, props, weapons, tools, and other FiveM resources in one place.

SantosCAD focuses on resource listings, source links, setup information, and known issues.

## Website

https://santoscad.org

## What We List

SantosCAD covers:

* Scripts
* EUP
* Vehicles
* MLOs
* YMAPs
* Props
* Weapons
* Developer tools
* Server tools
* Other FiveM resources

Each page aims to provide:

* Resource creator
* Resource type
* Official source
* Framework support
* Requirements
* Installation steps
* Configuration notes
* Known issues
* Documentation
* Support links

## Sources

We link to the original source when one exists.

Accepted sources include:

* Developer websites
* GitHub repositories
* Tebex stores
* Cfx.re releases
* Project documentation
* Creator approved download pages

We do not accept:

* Leak sites
* Cracked resources
* Stolen resources
* Paid resource bypasses
* Reuploads without permission
* Unauthorized download mirrors

## Contribute

SantosCAD accepts community contributions.

You may add a resource, fix a listing, update a link, or add a known issue.

### Submit a Change

1. Fork this repository.
2. Make your changes in your fork.
3. Check your information and links.
4. Commit your changes.
5. Submit a pull request.
6. Our team will review your pull request.

Follow the page format used by existing listings.

Use source information from the resource creator when possible.

## Page Format

Every resource page should follow the same structure.

Use this order when the section applies:

```text
# Resource Name

Short description

## Resource Information

## Overview

## Features

## Requirements

## Installation

## Configuration

## Known Issues

## Compatibility

## Links

## Credits
```

Keep pages easy to scan.

Use short sections.

Use headings for each topic.

Use bullet points for features, requirements, and issue lists.

Use code blocks for:

* Config values
* Resource names
* Commands
* `server.cfg` lines
* Lua examples
* JSON examples

Do not fill pages with large blocks of text.

Do not copy full documentation from the resource creator.

SantosCAD should explain the resource and send users to the source for full documentation.

## Writing Rules

Write all pages in clear English.

Use correct spelling and grammar.

Use short sentences.

Use active voice.

Write directly to the reader when instructions apply.

Example:

```text
Place the resource inside your resources folder.
```

Do not write:

```text
The resource should be placed inside the resources folder by the user.
```

Keep wording simple.

Do not use slang.

Do not use filler text.

Do not make claims without a source.

Do not guess features, requirements, framework support, or compatibility.

Use the same spelling for names across the page.

Examples:

```text
FiveM
QBCore
Qbox
ESX
ox_lib
ox_inventory
Cfx.re
GitHub
Tebex
```

Do not change the spelling of project names to match normal English grammar.

Use creator supplied names when available.

## Grammar and Spelling Checks

Before you submit a pull request, check:

* Spelling
* Grammar
* Punctuation
* Heading names
* Resource names
* Creator names
* Framework names
* Link text
* Code examples

Use complete sentences in descriptions and instructions.

Use sentence case for normal headings.

Keep code, resource names, file names, and config keys unchanged.

Bad:

```text
This script lets u setup ur inventory and has alot of options
```

Good:

```text
This script provides an inventory system with item metadata, stashes, shops, and weapon support.
```

Bad:

```text
Make sure ox lib is installed or it wont work
```

Good:

```text
Install ox_lib before starting the resource.
```

## Add a Resource

Include:

```text
Resource Name
Creator
Category
Official Source
Framework Support
Requirements
Installation
Configuration
Known Issues
Documentation
Support
```

Do not guess missing information.

If you do not know a value, leave the field out or mark the value as unknown.

## Update a Resource

Submit an update when:

* A link stops working.
* A creator changes a source.
* Requirements change.
* Framework support changes.
* Installation steps change.
* Documentation changes.
* You find incorrect information.
* Users report a known issue.

Provide a source for your change when possible.

## Pull Requests

Keep each pull request focused on one resource or one group of related changes.

Before you submit:

* Check your links.
* Check the creator name.
* Check the resource name.
* Check framework support.
* Check requirements.
* Check spelling and grammar.
* Follow the page format.
* Follow the Markdown format.
* Remove claims without a source.

Use a pull request title such as:

```text
Add ox_inventory
Update ox_inventory links
Fix ox_inventory requirements
Add known issue for ox_inventory
```

## Resource Ownership

SantosCAD does not own the resources listed on this site.

Each resource belongs to its creator or rights holder.

SantosCAD provides information and links to source pages.

A listing does not mean SantosCAD owns, maintains, supports, or distributes a resource.

## Resource Owners

If you own a listed resource, submit a pull request to update its page.

Contact the SantosCAD team for:

* Wrong ownership information
* Broken source links
* Outdated information
* Listing disputes
* Removal requests
